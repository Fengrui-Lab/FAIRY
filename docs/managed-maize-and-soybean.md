## 单场玉米为什么需要管理

田块为64垄，每垄268m、垄距0.65m、单行、株距25cm，种植面积11148.8m²（16.7232亩），全田播种68608粒。64垄来自当前固定探头布局；本轮没有泛化任意垄数。

初始营养指数为0.66；土壤为均匀的普通壤土参数：模型有效蓄水层1.0m、田间持水量0.34、根层日排水系数0.04、降雨截获效率0.90。这里的蓄水层是模型参数，不能解释为幼苗已有1m深根。所有初态在播前一次配置，没有在季中强设缺水、病害、成熟或产量。

| 阶段 | 实际任务与参考路径 | 为什么这样管理 |
| --- | --- | --- |
| 播前 | 读作物规则、天气、土壤和库存；平地、200kg底肥产品、起垄、挂玉米播种机，逐趟最多4垄播种 | 设备、物料、播深、株距和土壤条件都由真实工具校验 |
| 出苗 | 读取全田状态与六区探头；无人机全田巡查；机器人仅抽查0–3垄 | 区分全田遥感覆盖与有限的地面抽样 |
| 营养生长期 | 确认V6与营养状态后，全田分区追肥6kg/垄；施后复查公开营养值 | 正常初态需要季内营养补给；肥料量是模拟产品质量，不是纯氮量 |
| 吐丝期 | 状态、连续墒情、冠层、健康抽查和降雨预报共同复核后，补水20mm；次日复查 | 固定种子下少雨与墒情支持一次关键期补水；设施运行4小时另加5分钟设置 |
| 灌浆期 | 检查实际R3、墒情和降雨预报，暂不灌水，次日检查自然降雨 | 该窗口有有效降雨，不能因为到了日期就再灌20mm |
| 成熟收储 | 确认R6、籽粒水分≤30%、无雨、土壤可通行；挂玉米割台，逐趟收卸，必要干燥后入库 | 生理成熟、可收割和安全储存是三个不同条件 |

全季参考投入：肥料产品584kg（200+64×6），灌溉20mm，用水上限30mm、肥料产品上限650kg。无确诊病虫害时不施药；健康抽查仍是完整管理的一部分。

参考路径的等待是固定天气下已核验的巡查计划。它不是任意天气输入下会自动重新规划的控制器；Agent 应按实际观测调整。`get_ridge_range_state` 提供田块公开状态，探头和无人机有噪声，不能把物理内部根区含水率冒充Agent直接可见的数据。

## 双场如何组合

| 配置 | `maize_field` | `soybean_field` |
| --- | --- | --- |
| App名称 | `MaizeFarm` | `SoybeanFarm` |
| 作物/品种 | maize / MAIZE_EARLY_2026 | soybean / HEINONG84 |
| 几何 | 64×268m×0.65m，每垄1行 | 64×268m×1.1m，每垄2行 |
| 种植面积 | 1.11488ha | 1.88672ha |
| 株距/播深 | 25cm / 5cm | 8cm / 4cm |
| 全田种子需求 | 68608粒 | 428800粒 |
| 固定传感器 | `Maize_Sensor` | `Soybean_Sensor` |
| 固定灌溉 | `Maize_Irrigation` | `Soybean_Irrigation` |
| 参考肥料产品 | 底肥200kg＋追肥384kg | 底肥200kg＋追肥128kg |
| 参考灌溉/水配额 | 20 / 30mm | 0 / 20mm |
| 收获条件 | R6，籽粒水分≤30%，maize_header | R8，籽粒水分≤18%，harvester |
| 产量记账口径/储存上限 | 14%标准水分 / 14% | 旧有效收获量（13%标签） / 13.5% |

两场从2026年5月15日07:00北京时间开始，使用同一地区、同一合成天气序列。玉米采用上述正常壤土，大豆采用较深、保水较好的土壤；各场各有独立物理状态和水量额度。参考路径在玉米营养期追肥、大豆初花期轻量追肥；玉米补水不触发大豆灌溉。

共享的只有一台 `Tractor`、一台 `Mavic3M`、一台 `Robot0` 和一个 `Warehouse`。没有给每个农场再复制一辆拖拉机或一份车载油箱。

1. 共享移动田间工具显式传 `farm_id`，例如 `Tractor.plant_seeds(farm_id="maize_field", ...)`、`Mavic3M.fly_survey(farm_id="soybean_field", ...)`。
2. 固定设施已绑定农场，例如 `Maize_Irrigation.irrigate(start=0, end=63, hours=4)`；它没有切场参数。
3. 装种、装肥、加油和退料只操作共享仓库和机器，不传 `farm_id`。种箱残种先 `return_supplies()` 再换种，不能把玉米种子播到大豆场。
4. 设备显式拥有玉米播种机、玉米割台、大豆播种机及原有机具。本场在类型化作物规则上显式要求大豆的 `soybean_planter`/`harvester`，工具说明和运行检查同时读取此配置，不改变旧大豆场景的兼容规则。
5. 每趟4垄收割后 `Tractor.unload_grain(batch_id=...)`。32个批次分别保存来源场、作物、品种和垄号；同一个粮箱不能混装两场粮食。
6. 仓库按具体批次 `dry_grain` 和 `store_grain`。设施上限14%与来源作物上限取更严格值，因此大豆14%仍不能入库。分别报告两作物数量，不把两种标准水分的总kg解释成统一单产。

共享时间只推进一次：拖拉机在大豆场作业时，玉米照常生长；无人机充电等待也推进两场。双场动作更多，某些巡查可能比单场跨到次日，这是实际耗时，不要求两个场景日期逐秒相同。

这一点在灌浆期有具体区别：单场玉米在8月8日检查未来降雨；双场检查已到8月9日02:15，当日实际天气已有14.24mm雨、表层均值约0.371，未来两日预报为3.37mm。双场暂不灌水的主要依据是已经湿润及继续有雨，应次日复查，不能把单场前一天的17.61mm预报复制过来。

## 验收和证据

`validate()` 检查全田播种、逐场追肥覆盖、关键期用水及额度、必要阶段观察、成熟收获、种子账和安全入库。双场额外按来源核对批次覆盖，不能用玉米成功掩盖大豆漏收，也不能用共享库存的总体消耗掩盖某一场没追肥。

测试执行公开工具，并导出到全新场景回放。缺追肥、缺关键期补水的对照仍推进被省略动作的原始耗时，确保不是靠改变日界或少经过几小时制造差异。双场分别省略玉米追肥、大豆追肥和玉米补水，核对被省略一场的结果、另一场的独立结果及共同时间。

本轮还修正了单场机器人/无人机的农场标识：绑定环境时直接使用已注册的 `FarmContext`，回执 `farm_id` 与固定探头、农场目录一致。App显示名不再被当成环境农场ID。无环境的历史单场入口保留原行为；作业时间和物理效果不变。

[最终运行与兼容报告](../validation_runs/managed_crop_scenarios_20261024/final/REPORT.md) 记录两场CLI、回放、测试、缺管理对照与旧315场景对比。该验证目录按仓库规则忽略。

最终隔离版本通过484项测试。两个新场景的Oracle执行、保存后的全新初态回放和评价均成功；全部App快照与时钟精确一致。旧315场景的业务结果、物理和时间轴不变；原有29个异常仍单独列出。旧玉米单场仅4处工具回执的 `farm_id` 从App名称更正为注册农场ID。

| 2026-10-24 历史版本固定种子参考 | 入库量 | 灌溉 | 肥料产品 |
| --- | ---: | ---: | ---: |
| 单场正常玉米 | 9308.73kg（14%标准水分） | 20mm | 584kg |
| 双场中的玉米 | 9300.63kg（14%标准水分） | 20mm | 584kg |
| 双场中的大豆 | 7623.84kg（旧有效收获量，13%标签） | 0mm | 328kg |

大豆保留既有水分相关的额外有效收获损失，这是用户确认保留的模拟记账规则。它不是从籽粒干物质严格折算出的13%标准质量；上述历史版本实际安全入库水分约8.3537%，不应把13%标签当成实际入库水分。地上部生物量包含籽粒，不可与籽粒生物产量重复相加。

单场等时对照：省略V6追肥少573.57kg，省略吐丝期补水少516.21kg。双场等时对照：省略玉米追肥少573.31kg，省略大豆追肥少47.36kg，省略玉米补水少508.11kg；另一作物入库量均逐值相同。省略管理的对照仍能完成收储，但正常管理验收会明确拒绝它们。

快照续跑先初始化同一场景，再加载共同时间、各场、设备和仓库状态。本场的局部作业规则由场景初始化提供；快照本身不携带这份规则配置，不能用于向不同场景移植规则。

MAIZE_EARLY_2026是虚构品种，大豆也沿用现有模型。天气不是2026年哈尔滨实测；这些参考用于检验管理、工具和资源链路，尚未完成真实品种的田间标定，不代表产量最优、现实预期产量或现实施肥处方。仓库干燥沿用现有不计实际时间/能耗的简化；本轮没有改变作物或环境模型系数。


## 2026-10-30 大豆收获窗口修订

L4 回放审计发现固定日期参考收获过晚。只修改三个 legacy Oracle 的末期等待，保留播种、水肥、天气和物理参数：双场与三场正常黑农84由39天改为34天；本页玉米＋大豆参考的大豆等待由17天改为12天，随后玉米等待由25天改为30天，玉米管理与收获的绝对时刻不变。

基础和详细任务说明同步强调：分别观测成熟、籽粒水分、降雨和通行条件，达到本场收割条件后及时收获，必要时收后干燥。收割水分上限与安全入库水分不同，不应为了在田间自然达到入库水分而无依据地久等。正常黑农84详细说明中的39天参考窗口已同步改为34天；天气不适合时仍须等待并复查。

L4 的旧 `job.json` 在 `scenario_kwargs` 中冻结了 `scenario_input` 和 `agent_task_override` 两份说明。历史回放保留它们；新跑应重新生成任务，或删除这两个覆盖字段，让场景根据 `detailed_briefing` 生成新版说明，仅修改源码不会刷新旧 job 内的文本。

本次固定天气候选扫描采用公开工具执行，雨天和水分过高的候选明确排除。更新后的完整执行、保存后从新初态回放、旧 Agent 轨迹重算及精确结果见 [L4 Oracle 修订核验](../validation_runs/oracle_revision_20261030/修订说明.txt)。上述2026-10-24数值为历史证据，不代表修订后的基线；新基线也不声称全局最优。
