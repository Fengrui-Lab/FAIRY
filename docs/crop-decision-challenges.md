# 玉米与水稻分区决策场景

这组任务在现有玉米 18 个、水稻 28 个基础场景之外新增 24 个 ID：10 个完整季 L3、从真实季节运行截取的 10 个 L2，以及 4 个定向操作 L1。玉米沿用 FarmWorld 与原生 WOFOST，水稻沿用 PaddyWorld 与 WOFOST 8.1。任务聚焦分区诊断、有限投入和作业窗口；没有新增作物生理模型或宣称完成田间校准。

## 场景目录

以下后缀同时提供 `scenario_{crop}_l3_{suffix}` 和 `scenario_{crop}_l2_{suffix}`。L2 从各自 L3 的实际 `diagnosis` 检查点开始，水肥、田间状态、设备、天气、时钟和原生模型历史一起恢复。

| crop | suffix | 决策内容 | 对照 |
|---|---|---|---|
| maize | zonal_water_priority | 六个传感器区、不同根区储水能力与共享水额 | 不处理、等量均匀分配、错区处理 |
| maize | zonal_nitrogen_recovery | 局部氮池亏缺与定向追肥 | 不处理、等量均匀分配、错区处理 |
| maize | compound_water_n_limit | 缺水、缺氮、共限与正常区的水肥分配 | 不处理、仅水、仅氮、均匀分配 |
| maize | staggered_water_priority | 同品种分三期首次播种，阶段不同的田区共用水额 | 不处理、均匀分配、错区处理 |
| maize | rain_aware_irrigation | 近期确定性预报与立即灌溉、等雨的取舍 | 不灌溉、预报雨前追加灌溉 |
| maize | rainy_harvest_window | 分区成熟、水分、通行性和雨间收储 | 错过收获窗口 |
| rice | zonal_water_n_allocation | 两田格供氮、耙后渗透和水层差异 | 不处理、仅水、仅氮、错区追肥 |
| rice | infrastructure_water_priority | 堵渠、漏埂和每天四小时供水窗口 | 不修复、全部修复优先、灌水优先 |
| rice | zonal_crop_protection | 虫、病、草组成不同，药剂库存及雨风约束 | 不处理、错区处理、两田均处理 |
| rice | rainy_harvest_capacity | 晚雨、600 kg 粮箱、1800 kg/天干燥能力 | 错过收获窗口 |

四个 L1 为 `scenario_maize_l1_targeted_irrigation`、`scenario_maize_l1_targeted_fertilization`、`scenario_rice_l1_targeted_protection`、`scenario_rice_l1_channel_clearance`。它们考查明确交代的局部执行目标和操作后复查；其通过不代表来源季的农艺决策已得到验证。

## 校准状态与验收

[可读校准报告](crop-challenge-calibration.json) 列出每个任务的 `calibrated` 或 `experimental` 状态、数值阈值、窗口预算，以及所有对照的结果和错误。生成产物同时保存逐任务独立回放证明。`calibrated` 仅表示当前确定性模拟世界内通过了列明的对照，不表示现实品种或地区试验已校准。

当前 24 个任务均通过来源续跑与独立物理状态回放，**16 个满足验收规则，8 个保持实验性**。四个 L1 均满足其局部执行合同。以下四个来源的 L3 和 L2 尚未通过决策考点验证：

| 来源后缀 | 保留实验性的依据 |
|---|---|
| maize / staggered_water_priority | 能完成分期播种与收储，但均匀和错区对照均触发作业限制；仅有效的不灌溉对照不足以验证阶段分配优先级。 |
| maize / rain_aware_irrigation | 全季用水为 160.3125 mm，对照为 180.3125 mm；干物质产量为 7819.14 kg，对照为 8548.96 kg。节水约 11.1% 同时减产约 8.5%，不符合保产门槛。 |
| rice / zonal_water_n_allocation | 来源季没有可用的缺氮信号，独立四组试验也未形成三天可辨识窗口。 |
| rice / infrastructure_water_priority | 参考顺序未优于可行的“全部修复优先”对照，其余优先级对照存在操作错误。 |

L3 检查资源守恒、期限、全部收获物安全入库及独立结果门槛；L2 检查指定观察日期、窗口投入预算和生物量或收储结果。L1 检查局部覆盖、剂量或修复/植保效果。三类均要求操作后的公开复查。验收不要求复制参考操作路径；L1 的交代剂量和目标范围属于该执行任务的明确合同。

生物学产量使用原生 `TWSO` 换算的干物质 kg；收储结果单列为 14% 含水率商品粮 kg。玉米局部水氮任务的生物量/产量门槛针对目录声明的目标垄区。玉米水额使用全田面积加权 mm，水稻使用渠道取水 m³，肥料为产品 kg。窗口预算是参考投入增量的 110%，L1 为 101%；零投入项目不得消耗后续资源。物理库存和整季限额仍同时生效。

对照保持相同的绝对时间和天气，修改目标管理操作，并补足被删操作的耗时。生物量对照不重用参考作物的收储批次安排。若操作违法、时间跨日错位或天气历史不同，报告保留该失败对照，阈值计算排除它。有效对照中取最强结果，与参考结果的中点构成门槛。节水比较要求双方产量差在 1% 内，并保留较高产量的 99%；不能用“比自己的参考产量高”掩盖相对立即灌溉的减产。分期分配任务另外要求至少一个可行的均匀或错区对照，仅优于不灌溉不算证明分配优先级。条件未满足时，任务保持 `experimental`，其 `success` 始终为 false，另行报告 `execution_success`。正式评测必须排除实验任务，不能将其计作代理失败。

“错过窗口”对照是在同一时间线删除收获、卸粮、干燥和入库操作，以检验交付目标。它不证明最优收期或额外田间损耗。“均匀植保”使用现有工具在另一田格追加同类施药，可能耗尽库存；它不是等量半剂量试验。

校准结论仅覆盖报告中有效的对照。某个均匀或错区对照因工具前置条件而失败时，不能据此宣称已证明分配顺序最优；需要更强决策区分能力的正式基准，应继续补充可行的替代策略。当前参考策略均不声称全局最优。

## 公开观测与模型边界

- 玉米仍固定为 `Grain_maize_201`、64 垄；分期场景改变首次播种日期，不重种或重置已运行的原生作物。局部氮亏缺是预先安排的外部氮池事件，不伪装成自然淋失。模型氮遥测明确属于模拟遥测。
- 水稻田格可通过 `soil.puddled_sope_cm_day`、`soil.puddled_ksub_cm_day` 声明耙后水力参数；缺省仍为 1 和 0.2 cm/天。参数随初始配置、耙地事件和检查点一起保存，非法参数在建场时拒绝。
- 水稻氮信号仅在有日期的幼苗叶面积限制适用窗口内返回 `low`/`elevated`；未种植、缺记录、成熟或超出适用期返回 `unknown`，并附上日期、适用性和含义。它不是土壤氮传感器。水氮候选保存实际公开观测日期，目前缺少可辨识的氮信号，不能作为已验证的诊断题。其“仅氮”对照仅保留参考计划中原有的施肥，因此在参考未施肥时也不会凭空施肥。另行进行了七天“干/湿 × 低氮/高氮”的原生适配器试验，[结果](rice-nitrogen-observability.json)没有形成可区分水分充分条件下低氮与高氮的三天窗口。该试验隔离了生理代理，不包含机械和资源台账，不冒充完整场景 Oracle。
- 两类预报使用固定天气。玉米烘干没有真实能耗/吞吐模型；水稻的粮箱、作业时长和干燥能力是物理约束。未加入玉米授粉热害、倒伏、病虫害、多品种，亦未声称模拟水稻地下水管 AWD、苗龄育秧或完整反硝化。

## 生成和复验

```bash
uv sync --extra wofost
uv run python scripts/build_crop_challenges.py --verify-only
uv run python scripts/build_crop_challenges.py
uv run python scripts/summarize_crop_challenges.py > docs/crop-challenge-calibration.json
uv run python scripts/probe_rice_nitrogen_observability.py > docs/rice-nitrogen-observability.json
uv run --with pytest pytest -q tests/test_crop_challenges.py
```

标准 CLI 示例：

```bash
uv run fairy-run -s scenario_rice_l1_channel_clearance \
  --build-oracle --replay --evaluate --output-dir runs/rice_channel_clearance
```

支持 `--sources source_id,source_id` 选择来源季、`--output-root PATH` 输出到独立目录。生成无需 LLM 或在线天气。PCSE 需要可写的用户缓存；只读用户目录的 POSIX 容器可使用 `env -u USER .venv/bin/python ...` 让 PCSE 使用其临时目录后备路径。

`--review-only` 使用已校验的冻结参考和对照重新计算门槛，再逐任务完整执行及独立回放。它保留原作者摘要、原门槛和审查代码摘要，不重新模拟或替换对照；修改世界、管理策略或对照操作时应使用完整构建。本次用此路径修正了节水比较的产量条件，并要求分期任务具备有效的分配替代策略。

离线作者只依据公开工具输出作管理决策；私有状态仅用于保存检查点和评估。玉米计划保存为可审查的 Python 字面量，水稻计划保存为 JSON。运行时使用标准 `EventRegisterer`/`Engine`，不搜索、不优化、不自动重建缺失产物。加载会检查源码摘要、压缩包校验和、模型配置和计划摘要。

每个来源先在临时目录生成，再逐个任务检查：构图不改变世界、捕获执行与来源季后续完整物理状态相同、独立回放完整状态相同、验收符合任务状态。只有全部验证后才发布；并行来源使用短文件锁合并清单，清单最后替换，失败时保持拒绝加载。运行时检查场景和物理适配器源码摘要，离线复验另行检查公开策略及生成脚本摘要；改变相关代码后必须重新生成。安装后的运行时不依赖仓库的作者脚本。

水稻公开氮信号结构有变化，本次同步重建了旧水稻的检查点及固定计划。旧场景 ID、默认耙后参数和玉米基础场景配置保持兼容。

## 兼容性核验边界

本次实现基于目标分支提交 `5a5dca63ff07cef145b1b42ef6ae27e42f5babf0`。新任务逐个完成纯构图、来源续跑、捕获执行与独立回放；另用标准 CLI 验证了水稻疏渠任务的 build/replay/evaluate 流程。这里记录的是模拟器与 Oracle 核验，未运行 LLM Agent 评测。

兼容回归发现旧基线 normal 玉米的四个收储子任务在镜像投影中存在最大 `5.684341886080802e-14` 的末位舍入差异。原始分支快照也能复现；原生模型、收获恢复、库存和随机状态完全一致。该续跑测试现在仅对累计蒸发、累计蒸腾、冠层覆盖和 LAI 四类镜像浮点字段使用 `abs=1e-12, rel=0`，其他字段仍精确比较，并添加保护用例检查原生状态和库存的微小变化仍被拒绝。新增任务的完整状态摘要比对保持精确。

最终累计通过 364 项相关测试：新增挑战测试 44 项、核心回归 63 项、旧玉米/水稻兼容测试及比较保护测试 257 项。兼容套件分段执行，前段 81 项通过，续段 171 项通过；上述 4 项舍入差异在限定测试比较范围后重新通过，新增保护测试也通过。24 个新增任务另全部完成独立物理状态回放，当前校准状态为 16 个 `calibrated`、8 个 `experimental`。这些结果不代表整个仓库测试套件或 LLM Agent 评测已运行。
