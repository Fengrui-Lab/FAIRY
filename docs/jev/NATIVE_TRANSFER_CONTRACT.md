# 原生干燥与装载契约 · 2026-11-04

这是用户单独授权的原生工具修复，独立于 `enforced_tool_adaptor`。开关仍只控制 Jev 强化策略；原生修复对所有控制器有效。历史冻结运行和评分保留原版本，不将此次原生变化混称为适配层消融。

## 干燥

`FarmWorldApp.dry_grain` 拒绝没有待处理粮重的调用，返回 `error` 和 `code=no_pending_grain`，不改变干燥标志、含水率、库存或已存粮。湿批正常干燥、已安全批明确返回 `drying_skipped`。不借空批调用修补已入库湿粮。

## 装载

Tractor（单农场及共享机具）继续按空余容量截断，库存不足仍拒绝；Paddy苗、肥料及燃油保持整次精确转移，超量拒绝。旧字段保留原意义，例如 `loaded_kg` 和 `fuel_tank_l` 仍为总载量。

成功及满载无转移回执新增 `resource-transfer-v1`：

| 字段 | 含义 |
| --- | --- |
| requested | 请求增加量 |
| transferred | 本次实际增加量 |
| onboard | 转移后机载总量 |
| remaining_capacity | 转移后剩余容量 |
| inventory_remaining | 转移后仓库剩余库存 |
| unit | L、kg、seeds 或 seedlings |
| transfer_status | completed、partial 或 no_op |

`partial` 表示本次请求被容量截断，不是田间覆盖完成比例。`no_op` 表示未转移，不算装载完成。失败保留错误，Paddy分开产品、库存与容量原因；数值非法及库存拒绝不改变机载/库存。单农场成功换种仍采用旧的标签语义，但失败和满载无转移不再提前改品种标签。未新增退种动作，不改变共享设备异品种限制。

## Jev

已有强化候选按库存与剩余容量取界，并保留合法未知信息降级。干燥候选已有空批及容量检查，安全状态按当前批次证据判断，不用全局 `grain_dried` 给新批次背书。本轮补充实际转移字段到回执摘要，满载调用标记 `no_op`，与有效完成次数分开。原始workflow仍完整保留。

水稻插秧、UTC日边界、作物动力学和评分没有改动。工具源码指纹变化导致四个Rice挑战来源需更新来源身份：独立目录对旧/新工具的未隔离任务做物理终态、指标、验证和重放等价比较后，仅迁移 `source_digest` 与压缩文件校验和；原计划、检查点、终态期望值与参考指标原样保留。未修复既有终态指纹不匹配，也不解除隔离。
