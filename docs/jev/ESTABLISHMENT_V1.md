# 强化Jev：建植依赖、作物周期与有效进展

2026-11-04。仅由enforced_tool_adaptor=true路径接入；默认false、Pure-LLM、原生工具、场景和评分不改变。
当前源码版本：receipt-establishment-v3.1、task-management-v3、bounded-model-view-v7、
scoped-decision-context-v5、temporal-progress-v4、public-state-semantics-v1.2。

## 明确处方的依赖参数

对单农场、完整覆盖且不重叠的显式`ridges lo-hi: CULTIVAR seed_spacing_cm=...`处方：

- 播种/补种先选择起点，候选与当前料斗品种、未建植/有证据的修复目标一致。
- 株距绑定目标处方；范围不能跨处方边界、不同修复目的或已知种子供给能力。
- 装种数量按待建植/纠正目标、原生每垄用种计算、实际机载数量及容量/库存推导。
- 品种/株距纠正可选择full_replant=true；已确认出苗后的缺苗恢复使用false。未知成苗状态不自动生成重建指令。
  false也可能由原生工具对未出苗垄执行重置，最终以实际回执为准。
- “播种时序约束”中明确且完整的先播/等待若干天/后播顺序可形成阶段参考；
  时间取前区实际完成播种的回执。缺少时间证据保留TIMING_UNKNOWN，不编造日期。

不将单田处方套给多农场、部分处方或重叠/不明确计划；这类情况沿用现有菜单与模型判断。
这是任务一致性约束，不宣称相应品种或株距是农艺最优。没有额外调用工具查询隐藏状态。

## 作物周期账本

first_planting_timestamps保留首次建植；planting_timestamps跟踪当前作物周期。
成功回执phenology_reset_ridges只更新真正被重置的垄，不能根据full_replant请求标志推定成功。
失败、未重置垄和仅补缺不重置的回执不改变生育年龄。全田水肥参考仍使用原建植锚点，
不因一部分补种将整田追肥日期后移；分组年龄单独跟踪实际周期。

机器人observations字典与农场ridges列表均可提供已取得的观察字段。
重建后旧品种/株距观察不再作为当前不符合项，直到重新取得相应证据。
观察覆盖仅失效于实际作业涉及的目标；未知范围作业保守失效该范围，日期变化仍不推定旧观察新鲜。

## 时间推进与防循环

充电完成是可选唤醒点，不是必须中断所有等待的全局截止；管理窗口与其他pending响应仍保留保护。
显式任务中的阶段参考也限制不能跳过的等待边界。

真实变更与有效进展分开：重复重启已符合处方的作物，或把正确品种改错，不能关闭防巡检压力。
补齐未播目标、纠正明确处方错误、回执确认的成苗改善可以构成进展。
该判据用于提示与报告去重，不能替代原生验证，也不证明未知作业没有农艺价值。

## 报告治理

长周期任务在内部按公开作物状态、有效作业、品种/株距变化、粮食和新错误计算checkpoint，
已有报告使用其不可变历史前缀比较，不将内部hash写入面向用户的报告。
查询、充电、同状态重复重建不会单独开放另一次相同报告；新错误、失败发送后的恢复、
实际地块/农场变化仍可报告。短任务不受该长周期报告去重限制。

模型近期视图只保留成功报告的发送事实，避免其自动生成全文再复制一遍农场状态；
原始报告文本、回执、工作流和评分轨迹仍完整保留。观察/失败回执保持完整结构。
5条/24h缓存和40KB输入保护未放宽，没有重新加入1500字节预览。

## v2：出苗与缺苗的证据边界

正式18项中的局部土壤约束场景真实复测发现：播种约两小时后，出苗巡检返回
`stand_fraction=0`；v1把它变为待补种目标。原生工具在出苗前即使收到
`full_replant=false`也会重置生育期。本修补只改变Jev适配，不改变这个原生语义。

- 出苗前/阶段未知的零值不是建植失败证据，不生成补种或额外装种待办。
  不按固定天数推断出苗或失败，不新增隐藏生长状态读取和模型/工具请求。
- 同一观察中的公开`emerged`、`growth_stage`/`stage`，或者同周期此前取得的
  出苗证据，可确认出苗。正的观测成苗比例本身也可证明已有出苗；与明确的
  出苗前标记冲突时保守处理。非法数值不作为修复证据。
- 已确认出苗后的不足成苗比例（包括后来完全损失为0）仍可生成补缺目标。
  明确品种/株距错误独立判断，在出苗前也保留纠正入口。
- 证据按当前作物周期顺序维护；实际重置会清除旧周期的出苗确认。
  后来取得的阶段信息不能追认旧零值为当前缺苗，需取得新的成苗观察。
- 补种回执的`stand_fraction_after`是作业成苗基数，不证明已经出苗，
  也不自动要求继续补种。再次缺苗修复须取得作业后的新观察。
- 模型当前视图对延后的诊断单独解释：它不是必巡队列；没有其他就绪农事时
  推进时间后复查。不生成成熟日期、补种截止或农艺诊断。

单垄公开查询、范围查询、机器人观察以及共享服务回执均通过同一证据路径。
完整处方、单农场范围等v1限制不变；不能声称本补丁覆盖所有未解析任务。
true的元数据记录`receipt-establishment-v2`；false和Pure-LLM不接入这一策略。

## v3：启动前发现的补缺饱和循环

在隔离仿真的原生工具检查中，确认出苗后的补缺把成苗比例0.82提升到0.92，
没有重置；下一次相同补缺仍返回0.92。v2虽然要求新观察，但新观察仍低于1，
可能反复开放同一个无改善目标。

v3只依据本周期真实非重置补种回执：若成苗比例未改善或下降，记录该目标的
结果值。相同数值的新观察不再自动要求重复补缺；时间/阶段变化本身不清除这个
阻塞。成苗观测实际变化、明确品种/株距错误或新作物周期仍可重新评估。
程序没有硬编码0.92上限，也不把这种状态当作任务完成。
延后诊断及无改善摘要只列仍种植且未收获的垄，避免收获后继续显示旧恢复待办。

v3元数据为`receipt-establishment-v3`。启动前检查保存在工作区
`integration/jev-mini18-preflight-20261104`；包含正式18项初始菜单、真实工具的
隔离出苗/补缺探针、冻结启动预览及回归。它们不是真实Jev决策或产量实验。
默认false、Pure-LLM、原生工具和既有实验仍不变。

### v3.1：冲突观测不能清除无改善记录

第二轮离线复查发现一个边界缺陷：无改善记录建立后，插入明确未出苗或阶段
冲突的不同数值，会先清除记录；随后原数值又能触发补种。该组合由合成证据序列
复现，尚未在历史真实轨迹中确认，不能称作此前全季失败的新归因。

v3.1仅允许具有有效出苗证据的成苗变化清除记录。出苗前/阶段冲突的数值变化
保留原记录；后续确认的新缺苗、全损失、处方纠正与真实重置仍能进入原有恢复路径。
本次没有增加新的推理规则、等待期限、剂量或工具调用。
复查、版本预览及回归记录位于工作区`integration/jev-mini18-recheck-20261104`。
