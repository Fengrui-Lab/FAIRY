# 强化 Jev 的公共状态语义 v1

仅适用于 `enforced_tool_adaptor=true`。主路径为 `model_view.project` 与发送前
`request_guard`，实现为 `state_semantics.py`。不增加模型调用、工具调用、自动恢复或农业处方。
baseline、完整历史、重复检测、原生工具及内部精确账本不变。

## 表示与证据契约

- 数字键逐垄字典可编码为 `exact_keyed_columns_v1`：`row_keys` 保持次序，
  每列为 `constant` 或按该次序排列的 `values`。仅在编码更小时使用。
  `unpack_columns` 可精确还原 JSON 值，区分 bool 与数值；不平均、不舍弃尾垄差异。
- 重叠观测只有工具、模拟时间、范围外参数、结果元数据均相同，且重叠的实际行逐值相同，
  才可被后来的实际覆盖超集替代。不同工具、时间或读数不互相覆盖。
  各观测保留动作序号、来源、时间和年龄；年龄不等于有效期。
  仍沿用最多12个最新目标的有界缓存，遗漏数量明确记录；不是全部观测归档。
- 不选择同名指标的“真值”：不同来源的 `stand_fraction` 等仍独立保留，
  视图明确提醒来源/时点不可直接互换。未增加农业诊断或自动重播。

## 失败、生命周期与任务符合性

- 历史失败默认 `recovery_status=unknown`，不声称它仍是当前阻塞。
  只有后续同工具、同非范围参数的成功回执，其**实际覆盖**完全包含失败目标，
  才可解除该历史目标；分次覆盖可合并。仅补货、等待、请求范围、部分未知覆盖均不解除。
  改品种/株距的成功也不证明原失败目标已按原要求完成。
  历史工作流保留原错误；当前确定阻塞仍来自公开前置条件检查。
- management 与 temporal 共用同一个生命周期识别函数。未识别标 unknown；
  解析不到施肥处方不再用空待办暗示管理已完成。仍是受限语言识别，不是通用自然语言理解。
- 模型视图将施肥剩余量明确命名，播种/收获事实分别呈现；`bare` 阶段也保留 planted 标志。
- 播种回执按相邻垄、同一 UTC+08 播种日聚合为 cohort。年龄给出向外取整的0.01日边界，
  不用“最后播种3天”代表整个田块；内部逐垄秒级时间保留。这不是成熟预测。
- 用已有明确分区语法比较已获取的品种/株距观测，保留来源、动作序号和时点。
  不支持/重叠的目标标 unknown；未观测字段不判为符合。
  比较是带日期的证据，不自动修改 done 规则、不代替原生验证、更不自动重播。
- 非水田不附加水田浸田说明；零待处理粮食不附带未知含水率的干燥警告。
  未知待处理量和已知不安全入库证据仍保留。

## 预算与验证边界

输入保护仍为本地 UTF-8 JSON 40,000字节，回答余量8,000字节；不是服务 token 硬上限。
先无损列式编码，再按原机制移除可选近期事件/累计完成摘要；受保护内容仍放不下时停止发送，
不截任务、不改候选、不丢未确认解除的错误，也不无限重试。

本轮 mixed_stress 79步历史轨迹重建：请求40,180 → 38,633字节；baseline 同轨迹请求
逐值相等。离线发现18垄品种偏差，另1垄株距偏差。只是输入重建和规则检查，
没有真实模型复测，不证明任务表现改善，也不保证所有场景和长历史都能适配预算。
工作区证据位于 `integration/jev-state-semantics-fix-20261104`。

## 真实复测后的整数键补丁 v1.1

同日真实复测50步后在42,979字节本地保护停止。原生 Robot 的 observations 是
`dict[int, dict]`；JSON归档会把键变成字符串。v1仅对字符串键启用列式编码，
所以前述归档轨迹的压缩收益不能直接代表线上内存对象。恢复原生整数键后已精确复现失败。

`public-state-semantics-v1.1` 同时接受非负整数键和数字字符串键，保留 row_keys
原类型，不合并相同拼写的不同类型键。相关30项测试通过；同50步轨迹离线为39,463字节，
可通过保护。失败运行冻结源码不变，没有自动二次真实复测。详见工作区
`integration/typesafe-mini-mixed-state-semantics-retest-20261104/REPORT.md`。

## 用户指定的历史淘汰策略：bounded-model-view-v4

本节替代前述“不丢未确认解除错误正文”的模型视图策略；不是修改原始历史或将错误判为已解除。
参考 manos-compatible 保留最近5条结果、每条1500字符的做法，强化版本采用以下明确工程限额：

| 项目 | 新规则 |
|---|---|
| 近期事件 | 最近5条 |
| 观测回执 | 最新5个工具/参数目标，超过86400模拟秒的旧回执移出视图 |
| 历史失败回执 | 最新5个目标，同样按模拟年龄淘汰；未知时间不自动过期 |
| 单条大结果 | 超过1500 UTF-8字节时使用标记为result_truncated的文本预览；尽量独立保留原生status/warning/error/error_code |
| 观测/失败列表 | 分别最多8000/4000 UTF-8字节，超出时移除最旧整条记录 |
| 整体请求 | 目标32000字节；先移除可选近期事件/累计完成摘要，再跨观测和失败列表淘汰最旧项 |
| 本地硬保护 | 仍40000字节，回答余量仍8000字节；受保护当前内容超过软目标可继续，超过硬保护仍停止 |

年龄只用于缓存淘汰，不宣称24小时是农业有效期。不根据历史条目消失判断任务完成、错误解除或从未观测。
`history_retention`标明age/count/bytes/request_budget等淘汰原因；result_preview表示结果部分省略，
它与之后的整条淘汰可能发生在同一条记录上，原因计数不能相加当作独立记录数。
预览不是可供程序反序列化的完整JSON，模型应结合明确标签阅读，原始结构仍可在工作流找到。

任务、候选、当前farm_now、管理进度/数值账本摘要、当前blocked_actions/last_blocker、剩余要求、
任务符合性对比不按这条历史缓存规则删除。原生工具、仿真、Oracle、评分与baseline false不变。
当前仍有效的原生错误若尚未被程序前置条件覆盖，历史正文淘汰可能损失线索；本策略不保证零信息损失。

同一真实失败50步轨迹，恢复原生整数键后，v1失败请求42979字节，整数键补丁39463字节，
v4有界保留为31016字节；最新5条观测仍在，部分采用预览。只验证离线输入与程序边界，
没有自动启动下一次真实实验。证据位于工作区 `integration/jev-history-retention-20261104`。

## 取消结果硬裁切：bounded-model-view-v5

用户指出1500字节裁切会损失观测内容，主代码改为 `whole-receipt-window-v1`。
本节替代v4预览及小字节预算规则，旧运行仍保留原冻结源码和评分。

- 观测和历史失败各保留最多5个最新目标；24模拟小时年龄淘汰保持。
- **取消单条1500字节预览**，保留的结果仍是完整结构，不生成result_preview/result_truncated。
- **取消观测8KB、失败4KB列表上限**；不因为小列表预算提前丢失最新结果。
- **取消32KB软目标**；整体请求只有超过原有40KB保护时，才先删除可选摘要，再按旧到新淘汰整条历史。
- 无损分组/列式编码保留；不强制裁切留下的字段、数组或字符串。
- 任务、候选、当前管理/阻塞和完整工作流不变；baseline false不变。程序内部账本仍完整。

v4真实运行302次工具选择请求中，129次包含被截断的观测，共188次截断观测出现（重复出现不能当独立样本）。
最长结果3893字节，部分预览在逐垄记录或字段名中间结束。它证明信息被移除，尚未证明所有循环由此导致。
v4运行走满300调用却未完成农季，不能只因没有溢出就把剩余问题归为模型推理不足。

同一较早50步轨迹离线重建，v5为34189字节，保留5条完整观测，未触发40KB保护。
这不是v5真实运行结果，也不保证任何场景都能保留5条；超过整体保护时仍可能淘汰整条。
证据位于工作区 `integration/jev-full-receipt-window-20261104`。

## normal退化审查：bounded-model-view-v6

v5真实normal复测出现生物产量损失81.60%，旧v1为7.79%。前23次动作一致，
第24次从等待变为播种当天追肥；当时没有观测缓存或裁切，不能归因于历史淘汰。
本轮只在强化适配层调整呈现，不改原生工具、剂量、合法性或参考时间算法：

- 恢复 `days_since_last_planting`，明确它是最近一次成功播种的排程锚点，
  不代表所有植株同龄或成熟。错期播种的cohort信息同时保留。
- 未完成追肥轮次显式标注 `UPCOMING_REFERENCE`、`DUE_REFERENCE` 或
  `TIMING_UNKNOWN`，并给出距参考时间的秒数。未来窗口不屏蔽合法工具，
  剩余肥料或已装肥也不再表述成“现在就施用”的指令。
- 灌溉摘要保留当前参考轮次索引。已取得新鲜根区观测且已有算法给出可行目标时，
  选项说明明确“检查不等于实际灌溉”，仍由模型结合天气/作物决定。
- temporal-progress-v3删除推导的“未观察垄”队列；只保存已经取得的覆盖证据，
  不将采样或分区检查扩充成全田义务。

仍保留v5整条回执、5条/24h缓存、40KB保护、无损编码、精确内部账本及合法参数。
这是候选修补，不宣称产量已经恢复。离线固定旧125步和新280步轨迹，共407节点，
修补前后剂量账本、窗口、工具集合和等待值一致；它不能替代真实模型复测。
证据与改前快照：工作区 `integration/normal-adapter-regression-review-20261104`。

## 建植闭环修补：bounded-model-view-v7

成功补种回执中的实际phenology_reset_ridges更新当前周期年龄；首次建植日期另存，
全田水肥参考不因局部补种整体后移。机器人observations字典也进入字段识别，
实际重建之后的旧品种/株距观察标为未知，不继续当作当前纠正指令。

current_decision.establishment单独呈现未播目标、有证据的处方/成苗修复目标及未知目标，
不在管理模块重复整套清单。报告采用发送事实，不再将自动生成的整份报告复制回模型视图；
原始文本仍在工作流。这是对“保留回执完整”的明确报告例外，观察/失败结果保持完整。

窗口/历史数量/40KB保护与玉米水肥换算保留。具体依赖、阶段语法和范围限制见
[ESTABLISHMENT_V1.md](ESTABLISHMENT_V1.md)；未声明所有自然语言场景均可确定性解析。
