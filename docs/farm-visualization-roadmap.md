## 保留的设计问题

以下项目记录问题、约束与后续验收方向；接口、数据格式与具体实现暂不确定。

| 议题 | 后续需要解决的问题 |
| --- | --- |
| 日志回放与信息对齐 | 明确运行来源和日志格式，关联运行 ID、命令 ID、观测与状态版本；对齐仿真时间、墙钟时间、时区、测量时间与效果生效时间，处理同一时刻的事件顺序、缺失及乱序。当前只回看实验台保存的快照，尚不支持导入任意日志并重建三维历史；没有状态证据时不伪造历史状态。 |
| 运行中场景的在线展示 | 研究如何附着已有运行、获取一致的初始状态和后续更新、处理断线重连与过期状态，并明确只读展示和控制权的边界；展示本身不能重复执行工具、采样或推进仿真时钟。 |
| 田块类型：旱地/水田 | 研究类型如何定义、创建或修改，与作物能力、土壤、水文模型及农事工具如何匹配，以及修改对已有运行的影响。现有大豆场景及其他非淹水稻作能力不能视为已支持水田水文。 |
| 田块形状、面积与管理单元 | 研究矩形之外的边界、坐标与单位、面积计算、垄/管理单元映射及作业范围；领域模型与三维几何须一致。现有展示平移或旋转不提供物理形状修改。 |
| 传感器位置与覆盖 | 分别定义实际位置、坐标、安装对象、覆盖范围及与田块/管理单元的业务绑定；研究如何配置、修改并保留历史语义。现有图标移动只改变展示位置，不改变实际覆盖。 |

## 其他后续方向

| 扩展 | 前置条件与验收方向 |
| --- | --- |
| 创建实验时修改几何、品种、土壤和设备 | 版本化配置校验；面积、种量、用水及产量单位一致；配置变更与实验身份及对照条件可追溯 |
| 任意田块边界 | 领域模型先支持非矩形管理单元，再验证面积、覆盖和作业范围 |
| 道路和农机路线 | 引入真实路径、通行、速度与转弯耗时，明确燃油等资源结算 |
| 从历史检查点分叉 | 完整保存作物、设备、库存、随机流、时钟、事件与待生效动作；恢复后结果与连续运行对齐 |
| 多农场共享设备 | 保留 farm_id 与 asset_id，验证唯一库存、仓库归属和共享时钟 |
| 多作物与水稻 | 按作物能力分别适配旱作垄与水田水文地块，独立处理生育阶段与评分 |
| 导入已有 FAIRY 结果目录 | 校验来源、格式和指标；没有快照的记录只显示日志与指标，不伪造三维历史 |
| Blender 资产流程 | 统一米制、原点、层次和细节级别；导出脚本位于项目外，模型失败可回退 |
| 批量研究对照 | 统一对照条件和指标口径，保留控制来源及审计辅助标记，再增加统计汇总 |

现有扩展点包括独立场景适配器、版本化公开与诊断 DTO、原工具目录、视觉布局绑定、持久化观测与事件。后续推进 FAIRY 2.0 时，应结合上述问题重新评估整合方案与验收范围，届时再决定合入。历史快照不能代替完整 WOFOST 检查点。

本次分支仅保存 FAIRY 项目内的实现、测试、文档及前端锁文件。同级 `farm-tools/` 为本地桥接、验收和来源记录配套资料，`farm-runs/` 为运行数据目录；两者均不随本分支提交，虚拟环境、依赖副本、构建产物与本机日志也不发布。
