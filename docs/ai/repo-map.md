# FAIRY Repo Map

- `fairy/controllers/engine.py` is the lightweight runtime entry point. It registers a shared `TimeManager`, dynamic-event scheduler, `SystemApp`, and automatic `FarmWorldApp` physics attachment.
- `fairy/apps/farm_world/` contains the migrated FARM app/action layer and physics orchestrator.
- `fairy/apps/paddy/` contains the separate rice world, observations, machinery, operations, infrastructure and drone apps. `PaddyWorldApp` advances one native model per hydraulic plot; it does not use the soybean ridge orchestrator.
- `fairy/physics/` contains the migrated FARM physics engines and profiles.
- `fairy/physics/rice_backend.py`, `paddy_waterbalance.py`, and `data/wofost/rice/` contain the rice PCSE/WOFOST adapter, continuous water/nitrogen ledgers, and pinned IR72 parameters. The soybean `wofost_backend.py` and Harbin `profiles.py` remain separate.
- `fairy/scenarios/baseline_farm_world/` contains FarmAgent-style scenarios with `scenario_input` and `oracle_solution()`.
- `fairy/scenarios/farm_world_physics/` and `fairy/scenarios/farm_world_fullseason/` contain ARE-derived event-graph scenarios captured by `EventRegisterer`.
- `fairy/scenarios/farm_worldpp_physics/` contains the migrated round-3 mid-season physics episodes used by `scripts/build_oracle_baselines.py --scenarios all`.
- `fairy/scenarios/farm_world_fullseason_v2/` contains the migrated Harbin L3 full-season v2 pool. The formal 90 scenario ids are tracked in `scripts/fullseason/formal_90_scenario_ids.txt`; registry import must include this package for `scripts/run_scenario.py --list` to expose them.
- `fairy/scenarios/farm_world_fullseason_v2/l2_l1_splits/` contains the selected Harbin L2/L1 split scenario package. `scripts/fullseason/selected_l2_l1_20_30_scenario_ids.txt` is the FAIRY manifest used by `scripts/build_oracle_baselines.py --scenarios selected_l2_l1_20_30`; it currently contains 50 source rows after combining the original selected L1 and selected L2 lists.
- `fairy/scenarios/rice/` follows the explicit v2 scenario layout: eight `scenario_full_season_rice_<variant>.py` L3 modules and twenty L1/L2 modules under `l2_l1_splits/rice_<sourcevariant>/`. Existing `scenario_rice_*` IDs are preserved. Start with `rice_scenario_catalog.py` (`RiceScenarioSpec`, `get_spec()`), one scenario module, `rice_scenario.py`, then `rice_scenario_helpers.py` (`init_rice_apps()`, `build_rice_events()`).
- Rice runtime uses standard `build_events_flow()` / `EventRegisterer` / `.oracle()` / `.depends_on()` events from `oracle_plans/<scenario_id>.json`. `farm_checkpoint_state.py` reads checkpoints from `l2_l1_splits/rice_<variant>/checkpoints/<label>.json` and verifies artifacts against `scenario_artifacts.json`. `validation.py` owns task/resource acceptance, and `evaluation.py` owns rice outcome metrics. The former rice `scenarios.py` and `reference.py` paths are removed; there is no parallel dynamic registration or `oracle_solution()` implementation.
- `scripts/rice_reference_policy.py` contains the observation-driven rice reference policy. `scripts/build_rice_scenario_artifacts.py` explicitly generates 28 fixed plans and 95 source-season checkpoints. Before publication, `verify_event_plans(staging, specs)` runs and independently replays every plan through registered scenarios and Engine, checking task acceptance and final state hashes from staged artifacts. It replaces the SHA-256/PCSE manifest last. Its optional `--output-dir` overrides the default `fairy/scenarios/rice/` output location. Plans also record initial checkpoint/configuration fingerprints and `expected_final_state_sha256`. Packaged artifacts bind PCSE 6.0.13, pinned in `uv.lock`; another 6.0.x version requires explicit rebuilding. Missing or incompatible artifacts raise a rebuild error; scenario setup and workflow capture never run a policy or generation fallback. `scripts/run_rice_reference.py` produces reference-season validation reports. See `docs/rice-foundation.md` for the workflow and model limits.
- `scripts/build_oracle_baselines.py` builds cached oracle yield baselines by running FAIRY `Engine.run_scenario_oracle()` and extrapolating FARM physics to maturity.
- `scripts/rebatch_fos_from_traces.py` replays FAIRY `*.agent_workflow.json` bundles against fresh FAIRY scenarios, then calls `fairy.scenarios.fos.evaluation.evaluate_fos()` to produce FOS summary CSVs.
- `fairy/controllers/agent_builder.py`, `agent_config.py`, and `research_strategies.py` contain FAIRY's migrated controller family layer: ReAct baseline plus ReWOO, planner-executor, reflection, skill-RAG, specialist, verifier, tree-search, critic, and graph-memory profile ids.
- `scripts/iclr_validation_runner.py`, `scripts/fullseason/run_l3_context_ablation.py`, and `scripts/fullseason/run_l3_skill_retrieval_experiments.py` are the FAIRY-native deepseek context/skill sweep entry points. They pass `detailed_briefing` through `--scenario-kwargs` and read FAIRY `run_report.json` artifacts instead of ARE `output.jsonl`. Rice currently supports only `detailed_briefing=false/true`; unsupported Kwoo/library/retrieval modes raise errors. Rice metrics are not integrated into the soybean FOS aggregate or a cross-crop score.
