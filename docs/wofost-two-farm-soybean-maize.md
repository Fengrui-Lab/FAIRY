# 原生 WOFOST 大豆、玉米双农场全季场景

场景 ID：`scenario_two_farm_wofost_soybean_maize_full_season`。
完整题设、初态、设备、静态 Oracle 和验收都在
`fairy/scenarios/two_farm/scenario_two_farm_wofost_soybean_maize_full_season.py`。
它不调用其他场景的初始化或 workflow；现有旧场景保持原样。

## 地点与品种

两块相邻的模拟农场共用法国北部/卢森堡边境附近 **49.4°N、6.2°E** 的天气格点，
采用 `Europe/Paris` 日历。NASA POWER 2019-03-01 至 11-30 的原始六变量、275天数据
已随仓库固定保存，运行不联网。保留 NASA LST 日标签，按相同日期标签提供场景日驱动，
没有将日数据伪装成逐小时站点观测。

| 项目 | 大豆场 | 玉米场 |
| --- | --- | --- |
| 农场ID | `soybean_field` | `maize_field` |
| 种子 / 原生参数 | `SOYBEAN_901` / `Soybean_901` | `MAIZE_201` / `Grain_maize_201` |
| 官方参数适用地区 | 法国北部 | 卢森堡、德国 |
| 几何 | 64垄，268m×1.1m，双行 | 64垄，268m×0.75m，单行 |
| 面积 | 1.88672ha | 1.28640ha |
| 播种目标 | 40株/m²，株距约4.545cm，播深4cm | 约6.67株/m²，株距20cm，播深5cm |
| 生长 | 64个独立原生PCSE模型 | 64个独立原生PCSE模型 |

这两个官方地区相邻，因此选取共同边境地点作区域迁移模型参考。
原始作物YAML字节和参数不改；这不是该地点2019年的田间校准或真实产量预测。
播种密度是明确的模型目标，原生适配仍仅按实际密度缩放初始生物量，不称田间最优。
土壤、初始氮、420ppm模型默认CO₂及机具是本题公开假设。肥料按46%N产品、0.7有效回收接入。
数据来源、哈希与小场先验详见
`fairy/physics/data/wofost/research/thionville_nasa2019_v1/README.md` 和 `manifest.json`。

## 管理与资源归属

`Soybean_Sensor`、`Soybean_Irrigation` 只绑定大豆；
`Maize_Sensor`、`Maize_Irrigation` 只绑定玉米。
只有一个 `Warehouse`、`Tractor`、`Drone`、`Robot`，田间移动作业显式给 `farm_id`。
种子、油、药、肥及粮批均在共同仓库记账；各场水与实际施肥额度独立。
两种作物需要不同后端配置，本场景在自己的 `setup` 中分别配置两场，场景属性明确为 `wofost`。

| 本地日期 | 参考管理 |
| --- | --- |
| 5月1日 | 无雨窗口依次准备与播种两场；玉米施200kg基肥产品，大豆不例行施氮 |
| 6月1日 | 冷春后检查出苗；固定传感器→无人机全田粗查→机器人各抽查4垄 |
| 6月10日 | 复核玉米营养，补充共享燃油，玉米一次追施200kg产品 |
| 7月1、15日，8月1、15日 | 玉米每轮30mm，次日复查；共120mm，留下30mm额度 |
| 7月5、20日，8月5日 | 大豆每轮30mm，次日复查；共90mm，留下30mm额度 |
| 8月20日 | 两场晚期灌浆复核 |
| 9月9日 | 大豆成熟和含水率约17%的无雨窗口，收获、卸粮、按需干燥、安全入库 |
| 9月20日 | 玉米成熟和含水率约23.57%的独立窗口，完成另一场收储 |

多数灌溉是在关键期根区下降、预计降雨难补足时补亏，并非每次都已发生水分胁迫。
8月1日玉米原生RFTRA约0.816，已有明确水分限制。参考计划不追满水额度，不采用每日小水。
不额外注入病虫草事件；当前原生玉米未支持病虫草，不给它安排植保任务。

Oracle按公开工具容量分趟：两场分别16趟播种和16趟收割；种子按30万粒种箱批量装载。
大豆每12垄一批、末批4垄，共6批；玉米每8垄一批，共8批，均经实际2t粮箱校验。
合计14个粮批。完整流程为280次真实工具调用，分布在13个主要农事/巡查日期，
其中大量调用是明确的机具更换、容量分趟、卸粮及来源批次处理，不是280轮农艺管理。

场景内的 `ORACLE_WAIT_SECONDS` 是扣除前序真实作业耗时后，到所列日期07:00的固定等待秒数，
并非作物参数或隐藏管理策略。变更田块几何、机械速度或流程时，需要重新核对这些等待。
Agent不受Oracle固定日期约束，必须依据自己读取的实际状态决定操作。
验收逐场检查原生模型成熟、64垄种收、种子与肥料账、来源批次及安全水分；不会用总粮重替代单场完成。

## 运行

在仓库根目录：

```bash
PYTHONHASHSEED=0 .venv/bin/python -m fairy.cli \
  -s scenario_two_farm_wofost_soybean_maize_full_season \
  --build-oracle --run-oracle-tools --replay --evaluate \
  --output-dir /tmp/wofost-two-farm
```

此命令执行写好的Oracle并从新世界回放、验收，不调用LLM。

本次实际CLI执行与回放均完成，任务验收成功：大豆入库 **8112.48kg**（13%标准水分，
约4299.78kg/ha），玉米入库 **14272.00kg**（14%标准水分，约11094.53kg/ha），
两场分别64垄收获、14批全部安全入库。这是本场景管理后的模型结果，不是理论最高产。
执行命令、280步Oracle/回放与机器报告保存在桌面
`validation_runs/wofost_mixed_scene_20261026/`；`result_summary.json` 保留两个水分口径，
`run_command.txt` 记录完整命令。

本次另修正了 `FarmEnvironment.sync` 的当前天气投影：当原生世界在午夜结算昨天生长后，
共享Weather仍应显示今天的作业天气，避免按昨天雨量收割。修正不额外积分作物日，
已有默认日界的旧场景继续走原路径。
