# 新候选评价合同 v1（设计稿，未部署）

## 三组结果独立保存

1. **流程与终态**：64垄真实播种、原生成熟、真实收获卸粮、需要时干燥≤14%、严格安全入库、粮箱/接粮区清空，资源/设备/库存不负且守恒，配额未超。记录pass/fail/unknown及逐项原因。流程通过不表示产量管理优秀。
2. **实际粮食**：逐垄成熟TWSO kg DM/ha及按1.2864ha的加权全田量、真实回收干物质kg、实际14%标准入库kg、含水与转移/去水账。未达到成熟则成熟TWSO缺失并说明，不能把某日TWSO冒充成熟产量；零产必须有原生有效0证据。只做质量基准转换不伪造仓库已入库，不把干燥去水当DM损失。
3. **操作与恢复**：拒绝次数/类型/时间、是否实际投入、是否恢复、重复请求、等待及过期观测、pending与不确定结果；真实不安全行为与告警逐项保留。执行器护栏与Agent决策分开，自动等待不能记Agent能力。

## 旧validation.py如何使用

当前 `_audit()`把error_type、TOOL_ERROR、非空error/warning都追加整季failure。既有校验器/评分输出原样保留，作为legacy_native_validation。**不在本阶段或管线删除旧失败、覆盖Succ./Path Corr./KTC或重算自定义评分。**

以后只为新场景实现本合同，仍在FAIRY原生scenario.validate/CLI出口处理；独立测试后用独立身份发布。不直接继承旧“任何工具错误即整季失败”，也不把所有warning放过。可复用成熟、安全入库、预算与守恒检查；工具错误判定另行分类。旧记录与新合同不可混算通过率。

|情况|流程终态处理|操作与粮食处理|
|---|---|---|
|过湿灌溉或水分过高收获被拒绝，无投入/转移，随后恢复并合法完成|不因这一拒绝自动否决最终合格状态|保留拒绝和恢复；本次实际投入0；不能拿拒绝当农艺减产|
|单次warning含义不明、请求断开或返回部分结果|unknown待核对，不直接pass或fail|用公开回执/库存/日志核实，未知不填0、不自动重发|
|强制湿粮入库、未解决的不安全状态/真实越限行为|fail，后续安全状态不能抹去已发生的违规|保留原始警告、真实转移、损失；不统一豁免warning|
|超额真实施入、库存为负、账目不守恒、跨场景身份错|fail/invalid experiment，依实际问题分类|产量如可计算仍记录事实，但不能用来支持公平配对标签|
|模型/工具runtime崩溃、未完成全季、工具预算或时间耗尽|incomplete/unknown而非成功|保留有效观测/实际投入；成熟及存粮指标不得补造|
|安全入库但低产|流程可pass|粮食低产如实列出；不称管理能力已通过|

## 公平配对与E等级

按 `result_decision_rules.md`独立评估。流程失败不能直接拿仓库0与成功组比较称作水/氮农艺效应；允许已成熟TWSO存在时记录其差异，但不能据此通过“全周期可执行”门禁。原生错误本身不修剪轨迹、不跳过动作来强行评分。

这些是新场景建设验收规则，不给当前实验管线增添评分屏蔽条件。需要原生操作的输入缺失时仍明确缺失；终态/工具诊断不用于抹去其他可计算的原生指标。
