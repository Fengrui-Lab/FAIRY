Two crops. One recorded season.

This demo reads scenario_two_farm_soybean_maize_disease_water: 374 tool calls and 375 states, including the initial state, from 15 May to 18 October 2026. It needs no Agent, model service or live backend. All numeric values remain the original recorded simulation results.

Explore the farm plots

Select a plot in the 2D overview for its 3D view; select it again to return. Drag to orbit, scroll to zoom, and click a ridge or device for details. Plot selection keeps the global world time. Main moisture masks use root-zone volumetric water content (VWC). Ridge details also show the latest surface-probe reading, with its actual zone, time and age. These refer to different layers and times and are not averaged.

Bundled illustrations

The demo includes 15 AI-generated illustrations: 3 NDVI-style images, 6 soybean images and 6 maize images. They are local files in assets/media/simulated/. Exact prompts, built-in tool details and original-file provenance are recorded in ndvi-generation.json, soybean-generation.json and maize-generation.json.

Crop cards select an image for the recorded stage, condition, ridge and applicable time. Choose State schematic to switch from the simulated image to the code-drawn state view. Bare, unplanted and harvested states do not display a full green crop. These pictures illustrate a stage or condition; they are not reconstructions of individual plants and do not change numeric data.

The soybean follow-up image shows early green pods with residual spotting and yellowing. The maize follow-up retains visible water stress. Neither is photographic evidence or a claim of measured visual recovery.

NDVI images and recorded maps

Drone cards offer Illustrative image and Recorded ridge map views. The three AI-generated NDVI-style images contain invented illustrative pixel patterns, not reconstructed measurements or captured aerial imagery. Their full-field appearance does not extend actual survey coverage: events 159, 188 and 201 each cover only ridges 20–39, or 20 of 64 ridges. Numeric metrics and coverage remain derived exclusively from the recorded tool response; no diagnosis, severity or confidence is inferred from synthetic pixels.

The recorded map uses one actual value per ridge. NDVI has a fixed 0–1 scale; NDVI Detail uses 0.75–0.90 and is labelled Enhanced contrast. Canopy temperature uses 0–45 °C. The scales are shared across surveys, not stretched separately for each event. Missing and unsurveyed ridges stay distinct. Steps 110 and 115 contain no valid NDVI and do not show an NDVI example.

The survey selector includes only completed surveys available by the selected time. There is no post-treatment soybean drone survey or next-day post-irrigation drone image in this recording. Follow-up evidence comes from the actual ground, soil and crop-state checks.

Thirteen standalone numeric-map SVGs are bundled in assets/survey-maps/; its index.json records event, farm, scale and coverage. Optional regeneration uses node scripts/export-survey-maps.mjs from gui_demo. Node is not needed to view existing maps.

Timeline, workflow and tools

Each timeline slice shows the world after that tool call. Start is before the first call. Plot filters change visible actions while the world cursor remains global. The slider addresses all states; previous/next follows the selected plot's visible actions. Workflow hover previews an action without moving time; clicking selects and pins it. Dashed connections indicate filtered intermediate actions, not parallel execution.

The scene has 73 runtime tools, 72 exposed to an Agent, with 42 executed in this recording. The tool drawer shows source input schemas and the latest actual response available by the selected time. Formal output schemas are not declared. Downloads preserve original source wording.

Replay an operation

Successful field operations are illustrated as fixed home → recorded targets → fixed home. The same deterministic animation drives 2D and 3D, with work constrained by recorded coverage. Replay operation runs for 12 seconds without advancing world time, consuming resources or adding events. Field values remain the selected recorded post-action state. Returning home does not charge, unload grain or return supplies; only the corresponding recorded calls change those resources.

Reduced-motion preferences suppress automatic animation; explicit Replay operation can still play. Controls occupy a separate right-side rail. The backend models duration, fuel, materials, battery and charging but has no persistent device position, hover, landing or docking state. Fixed-home return and transit routes are UI conventions, not GPS or recorded physical transitions.

Material status

All 12 primary material slots are supplied synthetically: 3 NDVI examples, 7 event-support slots and 2 crop identity references. The 15 image files include extra stage variants, and some slots reuse a file. Four optional slots remain unsupplied: measured pesticide-residue data, equipment photographs, equipment models and measured GIS plot geometry.

No actual photographs, raw spectral or thermal rasters, image boxes or segmentation masks are supplied. Disease pressure is a model index, not a diseased-leaf percentage. Residual protection days are not pesticide-residue concentrations. Real observations and supporting illustrations must retain separate source labels.

The material checklist lists completed slots and optional requirements. materials.html accepts links and exports a catalog; browser edits do not write assets/catalog.json automatically. Review exported links before replacing the catalog. Keep captions in English and preserve event, time and ridge applicability. Data, models and GIS are collected for later integration, not parsed by the viewer.

Run locally

Use Python 3.10 or newer and a modern browser; 3D requires WebGL. From the FAIRY repository, run python3 gui_demo/serve.py on macOS/Linux or py -3 gui_demo\serve.py on Windows. If Windows lacks the py launcher, use python. From inside gui_demo, run python3 serve.py or py -3 serve.py.

Alternatively, run start-demo.command with sh on macOS/Linux, or double-click start-demo.bat on Windows. macOS also supports double-clicking the executable start-demo.command. Launchers resolve their directory, including spaces. Open http://127.0.0.1:4177; stop with Ctrl+C. Add --port 4178 if needed.

The server listens on this computer only. Use local HTTP rather than opening index.html directly. No pip/npm install or build is required; JavaScript, Three.js, the logo, recording and images are bundled locally. Guide and material pages remain directly available at /README.html and /materials.html.

Check, clone and share

Optional checks: node scripts/check-demo.mjs and python3 scripts/check-portability.py. On Windows, replace python3 with py -3. The portability check retains a copy in a path with spaces and checks static HTTP responses; it does not verify browser rendering. Its POSIX launcher check runs on macOS/Linux only. See VALIDATION.json for recorded validation results.

Keep the complete gui_demo directory and relative layout, including data/, vendor/, assets/, launchers and supplied supplementary_data/. Git clones include committed files only. Viewing needs no original-machine path. Bundled content works offline; optional external URLs may not. Browser-only material links do not travel with Git: export and review them before updating the catalog.

Regenerating the recording is separate from viewing it and requires the FAIRY Python environment. scripts/export_demo.py locates the repository relative to gui_demo; --repo selects another checkout. Use a new empty output directory. The exporter refuses to replace a nonempty destination and checks passive capture against results, state, random streams and timing. The browser does not load the full gzip audit.
