FAIRY 2.0 / LOCAL DEMO

Two crops. One recorded season.

This demo reads one executed scene: scenario_two_farm_soybean_maize_disease_water. It contains 374 tool calls and 375 global states, including the initial state. Simulation runs from 15 May to 18 October 2026. No Agent, model service or live farm backend is required to view it.

Explore the farms

The overview shows both plots in 2D. Select a plot for its 3D view; click the selected plot again to return. Click a ridge or device to inspect its values. Drag the 3D canvas to orbit and scroll to zoom. Shared tractors, drones and robots follow schematic trips to recorded operation targets; the same deterministic animation drives 2D and 3D. After each successful field operation, the device returns to its fixed home in the display. Positions and transit routes are UI conventions, not recorded GPS paths. Field values remain the selected recorded post-action state.

Replay an operation

Each successful field operation is illustrated as a trip from a fixed home to its recorded targets and back, with work constrained by the recorded coverage. Idle devices appear at their fixed homes. Returning home does not automatically unload grain, return supplies or charge; those effects require their actual recorded tool calls.

Replay operation runs a 12-second illustration. It does not advance world time, consume resources or add tool events. Reduced-motion preferences suppress automatic animation, while an explicit click on Replay operation can still play it. Controls occupy a reserved vertical rail on the right, outside the 2D/3D field canvas.

The backend models operation duration, fuel and material use, battery and charging, but has no persistent device position, hover, landing or docking state. Drone documentation describes automatic early return on low battery and sending a drone to its charging station with charge. Neither includes a recorded route or station coordinates. Normal successful completion does not specify whether the device remains aloft or lands. The fixed-home return is a display convention, not a recorded physical transition.

Read the timeline

Each selected slice displays the world after that tool call. “Start” is before the first call. Plot selection filters the visible actions, while the world cursor stays global. Shared equipment and global time actions remain visible. The slider addresses every world state; the previous/next buttons follow the selected plot's visible actions.

One view, with state and observations together

The main field view uses recorded simulation state. Soil moisture means root-zone volumetric water content (VWC). Clicking a ridge shows both this state and the latest acquired surface-probe reading, with its actual zone coverage, timestamp and age. These values refer to different soil layers and times; they are not averaged. The older two-mode switch has been removed.

Clicking a crop opens a fixed single-plant illustration for its recorded stage, disease pressure and water state. This deterministic drawing is a visual explanation, not a photograph or a reconstruction of an individual plant. The same crop, ridge and frame produce the same illustration.

Clicking a drone opens its latest completed survey. A ridge-by-ridge map is the main view, with NDVI and canopy-temperature modes and numeric values. Colors use a shared scale across recorded surveys rather than an automatic per-survey stretch. Optional NDVI Detail uses the narrower 0.75–0.90 display range and is labelled separately; the returned values do not change. Unsurveyed or missing values stay distinct. The map is a schematic rendering of numeric observations, not an aerial photograph.

The 13 standalone SVG maps are bundled in assets/survey-maps/. Its index.json records each map's event, farm, scale and coverage. To regenerate these optional exports, run node scripts/export-survey-maps.mjs from gui_demo. Node is required only for that export command, not for viewing the demo or the existing SVGs.

A selector lists previous completed surveys available by the selected time; future surveys never appear. The three requested supporting images have not been supplied. Existing plant illustrations and recorded numeric evidence remain available. External photographs can be added through the materials catalog and are labelled separately.

Natural plant colors and shapes follow the crop and stage. Geometry and positions are schematic; actual ridge dimensions and counts are retained. Harvested frames show stubble. A surface-probe zone value is not an independent measurement of each ridge. Ground disease detection is a boolean with confidence, not a measured severity percentage.

Explore the workflow and tools

Workflow category colors and farm lanes are independent. The paginated diagram includes every executed action. Hover previews its recorded post-action state without moving the world cursor; clicking selects and pins it. Dashed connections indicate filtered intermediate actions, not parallel execution.

The scene exposes 72 tools to an Agent, with one additional internal runtime tool. The sidebar derives availability from the exported toolset. Input schemas are from the source; formal output schemas are not declared. The drawer shows the latest actual response available by the selected world time. Downloaded source JSON retains original source wording.

Displayed values are recorded simulation results. Maize uses reference soybean parameters rather than a field-calibrated maize model.

Supply missing materials

The simulator returns numeric observations, not photographs, thermal rasters or bounding boxes. Photographic evidence remains empty until supplied. Deterministic plant and survey illustrations provide the default view and are explicitly identified as illustrations. Pesticide residual protection days are not pesticide residue concentrations. Use the checklist to add genuine measurements or clearly identified illustrations. Supplemental imagery is shown only in its declared event interval.

Run and regenerate

Viewing the recording requires Python 3.10 or newer and a modern browser; 3D needs WebGL support. From the cloned FAIRY repository, run python3 gui_demo/serve.py on macOS/Linux or py -3 gui_demo\serve.py on Windows. If Windows has Python 3 without the py launcher, use python instead.

Alternatively, run start-demo.command with sh on macOS/Linux, or double-click start-demo.bat on Windows. macOS also supports double-clicking the executable start-demo.command. Both launchers resolve their own directory, including paths with spaces. From inside gui_demo, python3 serve.py (Windows: py -3 serve.py) also works.

Open http://127.0.0.1:4177; stop with Ctrl+C. Add --port 4178 to a launcher or server command if the default port is in use. The server listens on this computer only. Use local HTTP rather than opening index.html directly. No pip/npm install, build, Agent service, simulator or model server is needed. JavaScript, Three.js, the logo and recording are bundled locally.

Clone and share

Keep the complete gui_demo directory and its relative layout. Git clones contain only committed files: add gui_demo/ before committing and pushing the branch, including JS/CSS/HTML, serve.py, both launchers, data/, vendor/, assets/ and any supplied supplementary_data/ files. Viewing does not depend on a path from the original machine.

Optional user-provided image URLs may require network access; the bundled demo does not. Material links saved only in a browser do not travel with Git. Export and review them before updating assets/catalog.json.

Run python3 scripts/check-portability.py inside the demo for a Python-only relocation check (Windows: replace python3 with py -3). It retains a copy in a path containing spaces and exercises static HTTP responses without opening a listening socket. It does not test browser rendering; the POSIX launcher check runs on macOS/Linux only. Node is needed only for the optional scripts/check-demo.mjs integrity checks.

Regeneration is separate from viewing and needs the FAIRY repository's Python environment and dependencies. The exporter resolves that repository relative to gui_demo; --repo can select another checkout. Run scripts/export_demo.py --output-dir /path/to/new-empty-directory. The exporter checks that passive capture preserves results, state, random streams and timing. It refuses to replace a nonempty destination. The large gzip audit is for inspection; the browser does not load it.
